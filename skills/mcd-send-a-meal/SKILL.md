# 麦麦代送 mcd-send-a-meal

给**别人**点一份麦当劳。核心不是"点什么"，而是"给谁点、点去哪、他能不能吃"。

## 这个 Skill 解决什么

自点的所有助手都在回答「我吃什么最省」。代送要回答的是另一组问题：

| 自点 | 代送（本 Skill） |
|---|---|
| 查我附近的门店 | 查**收件人地址**能配送的门店 |
| 用我的菜单 | 用**收件人所在门店**的在售菜单 |
| 用我的券包 | 按**收件人所在门店**重查可用券 |
| 按我的口味 | 按**收件人画像**（年龄/忌口/健康目标）配餐 |
| 送给我 | 送给别人，需要**配送追踪**和**收货确认** |

这四行差异是本 Skill 存在的全部理由。异地场景下，券和菜单都可能不一样，
直接复用本地下单的结论会出错。

## 使用前提

1. 已配置麦当劳 MCP 连接器（`mcd-mcp`，Streamable HTTP，`https://mcp.mcd.cn`）
2. 已建立收件人地址簿：项目根目录或 `~/.mcd-send-a-meal/contacts.json`
3. 每个收件人已有 `address_id`（用 `address-new` 子命令创建）

## 工作流程（严格按顺序，不要跳步）

### 第一步：确认收件人

用户说「给我妈点一份」时，先跑：

```bash
python scripts/send_a_meal.py contacts
```

把地址簿里有哪些人念给用户确认。如果用户说的称呼不在地址簿里，
告诉他当前有谁，并问要不要新建。

**不要自己编造收件人，也不要猜地址。**

### 第二步：出方案（只读，不下单）

```bash
python scripts/send_a_meal.py plan --to <称呼>
```

这条命令完整走完：收件人地址 → 可配送门店 → 真实菜单 → 营养约束求解
→ 目标门店可用券 → 官方核价。

拿到输出后，用自然语言向用户汇报三件事：

1. **门店**：选中哪家、距收件人多远、预计多久送到
2. **方案的取舍**：每组方案的热量/钠/蛋白，以及为什么推荐某一组
3. **钱花在哪**：商品原价、券优惠、配送费、最终应付——**要分开说**

> ⚠️ 汇报时不要把「商品原价 − 应付」直接说成"省了多少"。
> 外送有配送费，券的优惠可能被配送费吃掉一部分甚至倒亏。
> 必须把配送费单独列出来。

如果命令报错说「没有可行套餐」，**不要自行放宽约束**。
把卡住的约束原样告诉用户，问他要不要调整收件人画像。

### 第三步：等用户确认

把方案讲清楚后停下，等用户选。用户可能会说：

- 「就第一个」→ 记下序号
- 「他不能吃辣」→ 用 `--contacts` 指向的地址簿里改 profile 的 `avoid_keywords`，重新出方案
- 「太贵了」→ 说明当前已是最省组合，或提示可以去掉饮品

### 第四步：下单（必须显式确认）

只有在用户明确说「下单」「就这个」「点吧」之后，才执行：

```bash
python scripts/send_a_meal.py send --to <称呼> --combo <序号> --confirm
```

**`--confirm` 是硬门控。** 不加它只会预演、不会产生任何订单。
绝对不要在用户没明确同意时加这个参数——这是替别人花钱。

下单成功后把订单号和支付链接给用户，并提示可以用
`track --order-id <订单号>` 查配送进度。

### 第五步（可选）：生成给收件人的卡片

```bash
python scripts/send_a_meal.py card --to <称呼> --combo <序号> \
  --from-name "<落款>" --message "<一句话>" --out out/card.html
```

生成的卡片是给**收件人**看的：谁点的、这顿吃了多少、省了多少。
用户可以直接发给他。

## 收件人画像

地址簿里每个人的 `relation` 决定默认约束：

| relation | 默认约束 |
|---|---|
| `parent` | 钠 ≤1500mg、热量 ≤800kcal、去冰、忌辣忌冰、偏好粥/玉米/豆浆/鸡 |
| `partner` | 热量 ≤700kcal、脂肪 ≤30g、偏好沙拉/鸡/玉米 |
| `colleague` | 蛋白 ≥30g、热量 ≥500kcal、偏好鸡/牛/堡 |
| `client` | 热量 ≤900kcal、偏好牛/堡/咖啡 |
| `friend` | 热量 ≤1000kcal，约束最松 |

可以在联系人的 `profile` 字段里覆盖任意一项，例如：

```json
"profile": { "sodium_max_mg": 1200, "avoid_keywords": ["辣", "花生"] }
```

## 命令速查

| 命令 | 作用 |
|---|---|
| `contacts` | 列出地址簿和每个人的约束 |
| `inspect` | 打印 MCP Server 真实提供的 tool 与参数名 |
| `plan --to X [--json]` | 出方案，只读 |
| `send --to X --combo N --confirm` | 下单（`--confirm` 必填） |
| `track --order-id X` | 查配送进度 |
| `cancel --order-id X --confirm` | 取消订单 |
| `card --to X --combo N --out 路径` | 生成收件人卡片 |
| `address-new --name --phone --address` | 为收件人新建配送地址 |

所有命令都支持 `--dry-run`：用离线样例数据跑完整流程，不需要 Token，
也不会产生任何真实订单。演示和自测时用它。

## 红线

- **不下单**：没有 `--confirm` 绝不创建订单
- **不自动领券**：`auto-bind-coupons` 会改变账户状态，调用前必须问用户
- **不编数据**：营养表没收录的餐品如实说"未收录"，不按 0 计算
- **不猜地址**：地址必须来自地址簿，不要凭空构造
- **不静默放宽**：约束无解时如实报告并给放宽建议，由用户决定
